# ADR-0020: checkpoint の state を独立に再計算してから採用する

- 状態：採用
- 日付：2026-11-11
- 関連：ADR-0016、issue #97、#96

## 文脈

checkpoint は外部の書き手も作れる追記イベントである。state の形と親 OID が正しくても、title・権限台帳・コレクションなどの値が本来のイベントと一致する保証はない。形の検査だけでは、もっともらしい偽 state を通常の書き込みで再署名してしまう。欠落した collections/scratch は reducer の panic にもつながる。

## 決定

- 通常の読み取り・書き込みで checkpoint を起点にする前に、親コミットまでの全イベントを現在の reducer で再計算する。
- canonical 化した state の bytes と、親履歴から求めた max_event_id が checkpoint の値に一致することを確認する。
- 封筒 v が現行と異なる checkpoint は使わない。
- 一致した場合にも返すのは再計算した typed state とし、外部の map を reducer に渡さない。
- 不一致・復元不能なら既存の全走査へ戻る。fsck は従来どおり不一致を報告する。
- 書き手が自分であることや SSH 署名だけでは、実装バグ・古い意味論・侵害済み鍵による偽 state を排除できないため、検証の免除条件にはしない。

## 帰結

現時点で検証結果のローカルキャッシュは設けない。そのため checkpoint による過去イベントの読み飛ばしは性能面の利益を持たず、親履歴の全走査が必要になる。将来の高速化には、commit OID と reducer の版に結びついた、独立検証済みのローカルキャッシュを導入する必要がある。

fold 規則と正当なイベント集合の実体化結果は変わらない。checkpoint は引き続き fold から無視される最適化ヒントであるため、封筒 v・リポジトリ schema_version は昇格しない。
