# ADR-0010: ライセンスは MIT + forge のみ AGPL とする

- 状態：採用（配置方針のみ [ADR-0019](0019-forge-in-monorepo.md) で置換）
- 日付：2026-07-05
- 改訂：2026-11-12（PR #168。ライセンス選択は維持）

## 文脈

v0.1 公開に向けてライセンスを決める必要がある。
要求は次の 3 つである。

1. 仕組み（データ形式、`.workflows/` スキーマ、golden ベクタ）は誰でも使え、互換実装を歓迎する。plugin と標準化の賭けは採用の摩擦が少ないほど有利。
2. forge の実装だけは、フォークがプロプライエタリにクローズされない形にしたい。
3. 運用が面倒にならないこと。

## 決定

- 共有する core・app、CLI、TUI、MCP、クライアント、spec、docs は **MIT**。
- 将来の Forge 専用ソースは **AGPL-3.0-or-later**。配置は ADR-0019 に従い、同じリポジトリ・同じ Go モジュールの `cmd/githive-forge/`、`internal/forge/`、`web/` とする。
- ルートの `LICENSE` は MIT として維持する。Forge 実装を追加する最初の PR で、上記各配置先に AGPL の適用範囲を示す LICENSE/README、参照するライセンス全文、各専用ソースの `SPDX-License-Identifier: AGPL-3.0-or-later` を追加する。第三者コード・素材は元のライセンス表示を保持し、採用可否と配布義務を確認する。複数ライセンスから選択する依存は採用条件を記録し、MIT のクライアントに AGPL のみの依存を入れない。
- 既存の MIT ソースを本 ADR やディレクトリ移動だけで AGPL に変更しない。共有処理への変更は MIT の core/app に置き、Forge 専用コードを core/app や MIT のクライアントへ逆流させない。
- `githive` は Forge 専用コード・埋め込み UI をリンクしない。`githive-forge` と埋め込み UI を含む結合配布物は AGPL の条件に従い、利用する MIT コードの著作権・許諾表示も保持する。必要な対応ソースには、AGPL の要求に従ってビルドに用いた共有コード・UI・ビルド手順等も含める。共有ソース自体の MIT 表示は維持する。

## ADR-0019 による置換範囲

旧決定の「forge は実装時に別リポジトリとする」と、それを前提とする「MIT 側リポジトリ」「forge リポジトリ」という配置・貢献先の分離を置き換える。
**MIT の共有部分と AGPL の Forge というライセンス選択は置き換えない。**
同じリポジトリや go.mod を使うことは、すべてのファイル・配布物を同じライセンスにする根拠にはならない。
現在は Forge 未実装であり、この文書変更で既存ファイルを再ライセンスしたり、ルート LICENSE を変更したりしない。

## 理由

- MIT の共有コードを Forge が利用するときも元の表示を保持し、Forge 結合配布物について AGPL の義務を満たせる。逆方向の依存を禁止し、MIT として配る CLI に Forge 専用コードを混入させない。
- 配布や改変版のネットワーク提供では、適用される AGPL の対応ソース提供等の条件を満たす。MIT の仕様から他者が独自 Forge を書く自由は維持する。
- 配置はモノレポへ変更しても、専用ソースの適用表示・依存方向・成果物ごとの検査で境界を明示できる。

## 帰結

- AGPL を一律回避する組織には Hosted モードか互換実装という選択肢を残す。
- Forge 専用部分への貢献は AGPL、共有 core/app やクライアントへの貢献は MIT として受け入れる。同じ PR で両方を変更するときも、ファイルごとの表示と境界を維持する。
- P8 の最初の実装 PR で、ライセンス表示・依存一覧・結合配布物の対応ソース/notice を確認する。CLI が Forge 専用パッケージ・UI や AGPL のみで提供される依存を直接・推移依存に含まない検査を、ADR-0019 の逆向き import 検査とともに CI へ追加する。
- 本 ADR は法的助言ではなく方針の記録である。公開前に必要なら専門家の確認を挟む。
