# ADR-0023: 同一イベント ID の内容衝突を破損として拒否する

- 状態：採用
- 日付：2026-11-11
- 関連：#81、ADR-0004、ADR-0018

## 文脈

イベント和集合は ID を同一性とするが、従来は同一 ID に異なる内容があるとマージで後勝ち、チェーン読み出しでは走査順になった。マージ方向や次の書き込みによって状態が変わり、署名された履歴から一意の状態を得られない。

## 決定

同じ ref の履歴と、その ref をマージする入力集合について、同一 ID の封筒を全フィールド（未知の拡張フィールドを含む）の canonical JSON bytes で比較する。一致するコピーは同じイベントとして受理し、和集合・チェーン読み出しでは一度だけ返す。不一致は `conflicting_event_id` とする。勝者を選ばず、その ref のチェーン読み出し・追記・同期を拒否する。追記・同期は ref を進めない。fsck と verify は同じコードの問題として報告する。

比較は `event.IDSet` に集約する。Git のチェーン読み出し、チェックポイントによる読み出し、追記直前、マージの和集合でこの検証を通す。チェックポイントは過去の ID 衝突を隠せない。`log --since` は従来どおり限定走査であり、走査対象外の履歴の完全性は保証しない。全履歴の検査には fsck / verify を使う。

純粋な materialize.Fold の API は変えない。呼び出し側は検証済みのイベント集合を渡す。Python 参照実装も、内容が異なる同一 ID の入力は ValueError として拒否する。

## バージョン判断

一意の ID を持つ有効なイベント集合の fold 規則・実体化結果は変わらない。同じ封筒の複製は既存の「同一 ID は一つ」という集合の前提を満たす。破損データの恣意的な選択を停止する入力検証であり、勝者選択の新しい fold 規則は導入しないため、schema_version は昇格しない。

## 帰結

壊れた履歴は自動収束の対象外になる。管理者は競合するコミットを調べ、信頼できる履歴から別 ref に回復する必要がある。既存の署名済み履歴を書き換える自動修復は行わない。チェックポイントの利用前にも全履歴の ID 検査が必要で、未検証の高速化より一意の状態の保証を優先する。

一覧など既存の実体化スナップショット高速読出しは全履歴の完全性検査を実施しない。これはこの変更で保証する検証済みの fold 経路とは異なり、破損調査には fsck / verify を使う。
