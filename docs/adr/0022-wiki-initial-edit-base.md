# ADR-0022: 初回 wiki 編集は取得済みの wiki と共通の空ルートを基点にする

## 状態

採用（Issue #121）

## 背景

通常の clone は refs/projects を取得しない。ローカル wiki ref が無い場合に、現在の著者と時刻で空ルートを作ると、既存リモート wiki と共通祖先が無くなり、最初の save の通常マージが失敗する。

## 決定

- ローカル wiki ref が無い初回の edit は、選択された remote の refs/projects/wiki/main を明示的に取得する。ソースコードのデフォルトブランチや remote HEAD には依存しない。
- worktree の基点はローカル wiki ref、取得済み追跡 ref、共通の空ルートの順に選ぶ。
- `--no-sync` または取得失敗時はローカルの情報だけで編集を開始できる。
- 空ルートは固定の著者・日時・メッセージを持つ、署名しない空コミットとする。この合成ルートはユーザーの編集を含まない。実際の編集コミットの署名設定は変えない。
- 無関係な履歴を強制マージするオプションは使わない。

## 影響

別の著者・時刻・プロセスで同時に最初の wiki を作っても、同一の空ルートを共有し、通常の3-wayマージで統合できる。既存のローカル wiki 履歴は変更しない。

旧版で既に作られた独立ルートは書き換えない。リモートの wiki が一度も取得されていないオフライン clone では内容を復元できず、旧版の独立ルートとの統合には履歴の個別確認が必要である。
