# ADR-0031: エンティティ一覧の ID 列を一意な可変長プレフィックスにする

- 状態：採用
- 日付：2026-11-11
- 関連：#130、#129

## 文脈

ULID の先頭 8 文字は時刻の 1024 ms 窓で共有される。連続作成したエンティティの一覧が同じ ID 表示になり、そのまま show に貼ると曖昧になる。フィルターで一件だけ表示しても、入力解決はその feature の全 ref を対象にするため、表示中の行だけで一意性を判定できない。

## 決定

人間向けの issue list / task list / chat list の ID 列は、同じ feature の全ローカル ref に対して一意となる最短のプレフィックスを使う。最低 8 文字、必要なら完全な 26 文字まで伸ばす。archived 状態や表示フィルターで隠れた ref も比較対象とし、列幅も表示 ID に合わせて広げる。

計算は app/idresolve.DisplayIDs に集約し、JSON の完全 ID、保存データ、fold、通知の source.id は変更しない。一意性は一覧計算時のローカル ref 集合に対する保証であり、その後の並行追加・削除に対する永続的な別名ではない。

issue/task/chat show のコメント・note・message ヘッダにも同じ計算でイベント ID を表示する。chat --tail は切り出し前の全メッセージ（置換済みの原文を含む）で一意性を計算する。本文付き chat.create は初回メッセージでもあるため、その表示 ID は reply_to / supersedes の有効な対象とする。本文のない create はメッセージとして扱わない。

この変更の範囲は三つのエンティティ一覧の操作用 ID 列と show のイベントヘッダとする。作成結果・show は既存の完全 ID を維持する。自動通知のタイトルやタイムライン等の装飾的な短縮文字列は据え置き、操作用 ID としての一意性を保証しない。notify list / status / log 等の他の表示列については、この変更で保証したと扱わない。

## 帰結

一覧の ID を同じ feature の show 等へコピーできる。共通プレフィックスの長い場合は従来より横幅が広がる。schema_version は変更せず、JSON を利用する Agent の識別子も変わらない。
